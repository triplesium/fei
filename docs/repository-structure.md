# Repository structure

Entisium keeps the engine, Agent and Editor in one repository. Root directories
express product responsibilities; npm package boundaries express TypeScript
runtime dependencies. `packages/` is the existing xmake package repository, not a
JavaScript package directory.

```text
engine/                 C++ game engine and runtime protocols
runtime/
  native/               Native executable, control endpoint and snapshot support
  browser/              Browser executable, shell and project clock
agent/
  src/core/             Agent conversation and task execution
  src/prompts/          Entisium instructions
  src/models/           Model registry, credentials and streaming support
  src/tools/            Agent tool adapters over injected application services
  src/cli/              Standalone task entry
  tests/
devkit/
  src/contracts/        Browser-safe runtime commands, schemas and result types
  src/workspace/        Project and file services
  src/runtime/          Native process ownership, transport and session control
  src/mcp/              Standalone MCP adapter
  tests/
editor/
  src/browser/          Browser UI, chat and runtime presentation
  src/server/           Editor HTTP server, page relay, LSP and native folder picker
  src/shared/           Editor command contracts used by browser and server
  host/                 Legacy runtime-mcp-main.ts compatibility shim only
  tools/                Editor build and project bundling helpers
  xmake.lua             Editor, development and demo build targets
packages/               xmake dependency declarations
samples/                Example projects
tools/                  Generators and build helpers
```

## Dependencies

- `@entisium/devkit` imports neither Agent nor Editor code. MCP can run without
  loading the Agent or UI.
- `@entisium/agent` uses DevKit for application tools and CLI composition. Its
  `core` accepts injected models and tools and does not import Node application
  services or Editor code.
- `@entisium/editor` assembles both packages and supplies human-facing controls.
  Static Demo builds exclude the Agent and native adapters.

Cross-package imports use named exports such as
`@entisium/agent/core/agent` and `@entisium/devkit/runtime/session`.
`@entisium/devkit/contracts/runtime-tools` is browser-safe; native process modules
must only be imported by Node entrypoints. Model settings remain in Agent, including
legacy Editor-named storage files and environment variables for compatibility.

Do not introduce empty future subsystems. Resource processing, build orchestration
and inspection services belong under DevKit when implemented. Agent evaluation
would be a consumer of these APIs; no Eval Runner is included in this migration.

Browser code imports shared contracts, never server implementation. Server code
also uses those contracts and delegates project/runtime work to DevKit. The server
TypeScript configuration excludes browser implementation and tests. The legacy
`editor/host/runtime-mcp-main.ts` file remains only to preserve external MCP
configurations; there is no application implementation under `host/`.

## Build and development

The root `package.json` declares `agent`, `devkit`, and `editor` workspaces. Install
with `npm ci` at the root. There is one `package-lock.json` and one shared TypeScript
base configuration. Package output goes to `agent/dist`, `devkit/dist`, and
`editor/dist/server`. The server compiler also emits shared contracts under
`editor/dist/shared`; frontend output is `editor/dist/browser` or `editor/dist/demo`.

```powershell
npm run build:shared
npm run build:server
npm run build:editor
npm run build:demo
npm run typecheck
npm test
```

Shared package exports use compiled JavaScript by default. The `development`
condition selects TypeScript source for the CLI, MCP, Vite development server and
tests. Type declarations are generated by the shared build. `npm run dev --workspace
@entisium/editor` builds those declarations and watches the shared packages along
with the Editor server and browser. `npm run dev:server --workspace @entisium/editor`
starts only the Node service. `build:host` and `dev:host` remain compatibility script
aliases for `build:server` and `dev:server` respectively.

Xmake remains the engine and integrated Editor build entrypoint. Its Editor helper
tracks shared source/configuration changes and uses root workspace tools. It does
not move or change the xmake declarations under `packages/`.

See [Agent usage](agent.md) and [Native Runtime MCP](runtime-mcp.md) for standalone
execution and compatibility entrypoints.

Runtime executables live under `runtime/native` and `runtime/browser`. DevKit
launches and controls runtime processes; Editor presents their output. Runtime
build definitions are independent of Editor build helpers, which live under
`editor/tools`. Existing xmake target and artifact names (`entisium-runtime-host`,
`entisium-editor-runtime`) remain compatible.
